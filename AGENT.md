# Project Rules:
- Don't run `npm run build` after you change code.
- Don't run `npx eslint ..` after you change code.
- Don't run anything in terminal to check the code after you change the code.

## Plan and Execution Rules:
- create a plan inside issues folder
- The default format for a plan is YYYYMMDD/YYYYMMDD_issue_title.md, where YYYYMMDD is today's date.
- Don't create v2, v3, etc for an issue. If you have changed, modify it in the original file.
- When executing a plan, don't correct code that is not related to the solution you are implementing.
- Don't modify styling. Ignore the neatness of the code and focus on its functionality.
